# آموزش‌یار — سایت آموزشی اختصاصی برای هر مدرس

هر مدرس یک نسخه‌ی جداگانه از این نرم‌افزار می‌گیرد (دیتابیس و سرور خودش): سایت فقط خود او و دوره‌هایش را معرفی می‌کند، دانشجوهایش همان‌جا ثبت‌نام می‌کنند و از آموزش‌هایش استفاده می‌کنند، و خود مدرس ادمین سایت است.

پلتفرم LMS (مدیریت آموزش) با فرانت‌اند Nuxt 3 (بر پایه‌ی Vue.js)، بک‌اند Django + Django REST Framework، و پایگاه‌داده‌ی PostgreSQL. جزئیات کامل تصمیم‌های فنی و دلیل هرکدام در پوشه‌ی [docs/adr/](docs/adr/) مستند شده‌اند.

## ساختار مخزن

```
amozeshyar/
├── backend/       # Django + DRF — کل API
├── frontend/      # Nuxt 3 (Vue.js) — رندر سمت سرور برای سئو
├── docs/          # مستندات معماری و تصمیم‌های فنی (ADR)
└── docker-compose.yml
```

## راه‌اندازی سریع (لوکال)

### پیش‌نیازها
- Docker Desktop
- Python 3.12 به بالا
- Node.js 20 به بالا

### ترتیب اجرا

اپلیکیشن (بک‌اند و فرانت) مستقیم روی سیستم اجرا می‌شود؛ داکر فقط سرویس‌های زیرساختی را بالا می‌آورد، نه خود اپ. ترتیب درست:

1. **داکر را بالا بیاورید** (اگر Docker Desktop باز نیست، اول آن را اجرا کنید):
   ```bash
   docker compose up -d postgres redis minio
   ```
   این سه سرویس یعنی:
   - **postgres** — دیتابیس اصلی (کاربرها، دوره‌ها، سفارش‌ها و باقی داده‌ها)
   - **redis** — کش + صف کارهای پس‌زمینه (Celery از همین برای پردازش ویدیو استفاده می‌کند)
   - **minio** — فضای ذخیره‌سازی فایل سازگار با S3 (ویدیو، عکس، رزومه)؛ در production با یک فضای ابری واقعی جایگزین می‌شود
2. **بک‌اند را اجرا کنید** (بخش بعدی).
3. **Celery worker را اجرا کنید** (اختیاری برای توسعه‌ی سریع، ولی بدون آن آپلود ویدیو پردازش نمی‌شود).
4. **فرانت را اجرا کنید**.

### بک‌اند (خارج از Docker)

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate   # ویندوز
cp .env.example .env     # و مقادیر واقعی را در آن تنظیم کنید
pip install -r requirements/dev.txt
python manage.py migrate
# مدرس صاحب سایت (ادمین) + حساب توسعه‌دهنده (از DEVELOPER_EMAIL/DEVELOPER_PASSWORD در .env)
python manage.py setup_site --email ali@example.com --password '...' --first-name علی --last-name احمدی --headline "مدرس پایتون"
python manage.py runserver
```

مستندات API: `http://localhost:8000/api/docs/` (رابط Swagger) و `http://localhost:8000/api/redoc/`

> نکته‌ی مخصوص ویندوز: اگر پورت ۸۰۰۰ یا ۳۰۰۰ روی سیستم شما رزرو شده باشد (این اتفاق روی ویندوز به‌خاطر بازه‌های پورت رزروشده‌ی Hyper-V/WSL می‌افتد — با دستور `netsh interface ipv4 show excludedportrange protocol=tcp` قابل بررسی است)، کافی است پورت دیگری بدهید، مثلاً `python manage.py runserver 0.0.0.0:8100`. همچنین چون Nuxt به‌صورت پیش‌فرض ممکن است فقط روی `::1` (آی‌پی۶) بایند شود و از طریق `127.0.0.1` در دسترس نباشد، بهتر است فرانت را با `npm run dev -- --host 0.0.0.0 --port 3300` اجرا کنید.

### فرانت‌اند (خارج از Docker)

```bash
cd frontend
cp .env.example .env
npm install
npm run dev
```

اپ روی `http://localhost:3000` بالا می‌آید (یا هر پورتی که در `--port` مشخص کرده باشید).

### Celery worker (پردازش ویدیو)

```bash
cd backend
celery -A config worker -l info
```

روی ویندوز حتماً فلگ `--pool=solo` هم اضافه شود، چون Celery روی ویندوز از پول پیش‌فرضش (`prefork`) پشتیبانی نمی‌کند.

## ویژگی‌های کلیدی

- **یک نسخه = یک مدرس**: صفحه‌ی اول، هدر، فوتر و عنوان صفحه‌ها از پروفایل مدرس صاحب سایت ساخته می‌شوند. هیچ لیست یا اسمی از مدرس‌های دیگر وجود ندارد.
- **مدرس = ادمین**: مدرس از پنل مدیریت (`/admin`) دوره می‌سازد و منتشر یا پیش‌نویس می‌کند، سرفصل‌ها، ویدیوها و کلاس‌های زنده را مدیریت می‌کند، دانشجوها را می‌بیند و متن و عکس صفحه‌ی اول را از «تنظیمات سایت» عوض می‌کند. مرحله‌ی تایید دوره وجود ندارد.
- **ثبت‌نام فقط دانشجو**: یک فرم واحد ورود/ثبت‌نام (پاپ‌آپ شیشه‌ای در هدر/فوتر)؛ ثبت‌نام عمومی همیشه حساب دانشجو می‌سازد.
- **حساب توسعه‌دهنده**: در هر نسخه یک حساب superuser برای توسعه‌دهنده ساخته می‌شود که در لیست کاربران مدرس دیده نمی‌شود و مدرس نمی‌تواند آن را تغییر دهد یا غیرفعال کند.
- **آپلود ویدیو و پیش‌نمایش رایگان امن**: آپلود با پردازش خودکار در پس‌زمینه (ffmpeg + Celery) و تولید یک کلیپ پیش‌نمایش که *فیزیکاً* کوتاه شده (پیش‌فرض ۳۰ ثانیه، قابل تغییر) — نه یک محدودیت زمانی سمت مرورگر که با ابزار توسعه‌دهنده دور زدنی باشد. جزئیات کامل در [docs/adr/0003-video-preview-gating.md](docs/adr/0003-video-preview-gating.md).
- **ادامه‌ی یادگیری**: محل توقف هر دانشجو در هر درس ذخیره می‌شود؛ داشبورد یک میان‌بر «ادامه‌ی یادگیری» به آخرین درس نیمه‌تمام نشان می‌دهد.
- **پرداخت با زرین‌پال**: خرید دوره با درگاه زرین‌پال و ثبت‌نام خودکار و تراکنشی دانشجو در دوره بعد از تایید پرداخت.
- **سئو**: رندر سمت سرور برای صفحات عمومی (دوره‌ها و صفحه‌ی اصلی)، تزریق JSON-LD، تولید خودکار sitemap/robots.
- **طراحی**: تم شیشه‌ای/کریستالی (glassmorphism) یکدست در تمام صفحات، فارسی و راست‌به‌چپ.
